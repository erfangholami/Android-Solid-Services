*[ACL]: Access Control List — the resource that says who may read or write a Solid resource
*[ACP]: Access Control Policy — the policy-based authorization framework, used by Inrupt ESS
*[ACR]: Access Control Resource — the document ACP keeps a resource's policies in
*[AIDL]: Android Interface Definition Language — how Android describes a cross-process interface
*[AS2]: Activity Streams 2.0 — the vocabulary Solid notifications are written in
*[ASS]: Android Solid Services — the host app that holds the accounts
*[CRUD]: Create, read, update, delete
*[CSS]: Community Solid Server — the reference open-source pod server
*[DPoP]: Demonstration of Proof-of-Possession — binds an access token to a key only the holder has
*[ESS]: Enterprise Solid Server — Inrupt's pod server, behind PodSpaces
*[ETag]: A version marker a server returns, used to make a write conditional on nothing having changed
*[IPC]: Inter-process communication — how your app talks to Android Solid Services
*[JSON-LD]: A JSON serialisation of RDF
*[LDN]: Linked Data Notifications — the W3C protocol behind the pod inbox
*[LDP]: Linked Data Platform — the W3C spec Solid containers are built on
*[N3]: Notation3 — the syntax Solid patches are written in
*[OIDC]: OpenID Connect — the authentication layer Solid sign-in is built on
*[RDF]: Resource Description Framework — the data model pods store
*[SDK]: Software development kit — here, the `client` and `api` libraries
*[TTL]: Turtle — the RDF syntax most pod documents are written in
*[WAC]: Web Access Control — the ACL-based authorization system most pod servers use
*[WebID]: A URI that identifies a person and dereferences to their public profile
